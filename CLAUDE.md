# SportsChud

Windows desktop app (Electron 33, plain JS, no bundler/framework) that sends live game alerts for NHL, MLB, NFL, NCAA football (FBS) and NBA. Data comes from ESPN's unofficial public scoreboard API. See `README.md` for the user-facing description.

## Commands
- `npm install` then `npm start` runs the app (`electron .`).
- `Setup-SportsChud.bat` installs Node (winget, with a direct nodejs.org download as fallback) if missing or older than 18, then runs `npm install` if Electron is missing. `Setup-SportsChud.bat repair` wipes `node_modules` and reinstalls; `auto` skips the pauses.
- `Start-SportsChud.bat` is the end-user launcher: if `node_modules\electron\dist\electron.exe` exists it just starts it, otherwise it calls Setup first.
- `npm run dist` builds a Windows zip with electron-builder. CI (`.github/workflows/build.yml`) builds an NSIS installer on `windows-latest`.
- There are no tests or linter. Sanity check JS with `node --check <file>`.
- Target platform is Windows. Develop/edit anywhere, but tray, taskbar, shortcut and toast behavior can only be verified on Windows.

## Layout
- `main.js`: Electron main process. Window, tray, single-instance lock, settings, desktop shortcut, taskbar details, login item, IPC handlers, notifications.
- `engine.js`: polls ESPN (15s when a game is live, 60s otherwise; one poll at a time, a bad event is skipped, a poll that ends after `stop()` does nothing), diffs game state, calls `notify` on changes. Close-game thresholds live in `CLOSE_RULES`; `isExtra` defines what counts as overtime per sport (NCAAF reuses the `football` rules). Close-game alerts also fire on first sighting (app opened mid-game), once per game via `closeSent`. Also `fetchDays` (one request per day, ESPN rejects ranges) and `parseEvent`.
- `leagues.js`: league definitions and ESPN URL builders. Add a league by adding an entry here, including its `cols`, `sortStat` and optional `standingsLevel` for the Standings table. Standings use `/apis/v2/...` (not `/apis/site/v2`). Optional per-league fields: `scoreboardQuery` / `teamsQuery` (NCAAF passes `&groups=80` so ESPN returns all FBS games and teams, not just the Top 25) and `noInjuries` (league is left off the Injuries tab).
- Roster and Injuries: `fetchRoster` / `fetchInjuries` in `engine.js` (IPC `roster`, `injuries`), cached 10 and 5 minutes. ESPN rosters come grouped by unit (NHL/NFL/MLB) or as a flat list (NBA); `parseRoster` handles both. The injuries feed is league-wide and has no team logos, so `parseInjuries` takes the logo from the athlete's team or falls back to ESPN's logo CDN.
- Standings and Playoffs: `fetchStandings`, `isPostseason` and `fetchPlayoffs` in `engine.js`, exposed through the `standings`, `playoffs:status` and `playoffs` IPC channels. Playoffs has no bracket feed: series are rebuilt from postseason (`season.type === 3`) scoreboard events, whose `competitions[0].series` carries the running series score. The Playoffs tab is hidden unless `playoffs:status` says a followed team is alive (`followedAlive` in `engine.js`: in an unfinished series, or won the one that just ended) or the `playoffsAutoHide` setting is off. With autohide on, the Playoffs view only lists leagues with a live followed team. Status is refreshed every 30 min and whenever teams are followed or unfollowed.
- Who-scored detail in scoring alerts: when a followed game's score rises (`g.kind !== 'basketball'`, `score` alert on), `Engine.process` hands the alert to `queue()`, which calls `scoringDetail` to read ESPN's per-game summary (`summaryUrl` in `leagues.js`, `fetchScoringPlays` / `parseScoringPlays` in `engine.js`; `parseEvent` now sets `eventId`, ESPN's own id without the `league:` prefix). `playsBetween` picks the scoring plays that account for the change from the previous score to the current one; the feed can trail the scoreboard, so it asks again after `SCORE_DETAIL_DELAYS` (now, +4 s, +8 s) until the last play lands exactly on the current score. `cleanPlayText` strips ESPN's bracketed season totals and trims to 140 characters. The alert body is the play text (up to the last 3 plays) on the first line and the old score line below; if there is no detail (timeout, HTTP error, unexpected shape) it sends exactly the old plain alert, so nothing is ever lost. The second line is computed before the wait because the clock moves on. `queue` / `sendInOrder` keep one game's alerts in order: the overtime, period and final alerts go through `sendInOrder`, so they wait behind a scoring alert that is still waiting on detail. `Engine.stop` clears the queue and pending lookups send nothing once `stopped`. The summary payload (`scoringPlays` with `awayScore`, `homeScore`, `text`, falling back to `plays` flagged `scoringPlay`) is based on ESPN's usual shape and has not been checked against live data from this environment: if ESPN changes it, the symptom is plain alerts, so check `parseScoringPlays` first.
- Game panel (click a game on Scores or Recaps): `gameCard` cards carry `data-gid` and `renderScores` binds them to `openDetail(id, 'scores')`; Recaps cards (`.rcard[data-rid]`, inner buttons don't trigger it) call `openDetail(id, 'recaps', game)`. `state.detail = { id, from, game, tab, data, error, loading, settled }` is set while a game is open (`from` is the tab it was opened from, `game` the finished game snapshot for Recaps; `detailGame()` uses it instead of the live feed there, and `renderOrigin(from)` / `closeDetail` return to the right list), and while a game is open `renderScores` / `renderRecaps` call `paintDetail()` instead of drawing their list (hero from the live scoreboard feed in `state.games` for Scores, or from the stored finished game for Recaps; tabs Summary / Box score / Plays from the summary feed; the Summary tab is a `.dsum` grid, team stats 3fr | scoring summary 7fr, stacked below 1000 px window width, full width when there are no team stats), so the 30 s Scores refresh and `games:update` repaint the panel without losing it. Data comes through IPC `game:detail` (`api.gameDetail(league, eventId)`) = `fetchGameDetail` in `engine.js` (same `summaryUrl` as the who-scored feature, cached 10 s, at most 40 entries) which returns the normalized object from `parseGameDetail`: `heads` / `teams` (line score), `teamStats`, `scoring`, `plays` (newest first, max `DETAIL_PLAYS` 30), `players` (box score groups). ESPN's summary is undocumented and differs per sport, so `parseGameDetail` reads everything defensively: every list of objects goes through `objs()` (null or odd entries are skipped), football plays are found inside `drives`, and a missing section comes back as an empty array that the panel words as "nothing yet". The IPC handler only accepts a known league key and an event id matching `[A-Za-z0-9_-]{1,40}`. `openDetail` starts a 15 s timer (`DETAIL_REFRESH_MS`) that reloads only while the game is live (or until a finished game has loaded once, `settled`), skips while `document.hidden` (window in the tray), and stops when the panel closes, the game leaves the feed, or the tab changes (`setTab` clears `state.detail`). A failed refresh keeps the previous data and says so. The panel opens from Scores and Recaps; Schedules has its own cards. Like the who-scored feature, the payload shapes are written from ESPN's usual layout and have not been checked against live data from this environment: if a section is always empty, check `parseGameDetail` against a real `summary?event=` response first.
- Win probability and game leaders (Summary tab of the game panel): `parseGameDetail` adds `winProb` (`parseWinProb`: from the summary's `winprobability` rows, `homeWinPercentage` as a fraction or percent, sampled to at most ~60 trend points; otherwise the pre-game `predictor.homeTeam.gameProjection`; `null` when neither) and `leaders` (`parseGameLeaders`: the summary's per-team `leaders`, top player of up to `LEADER_CATS` (4) categories). `detailWinProb` / `detailLeaders` in `renderer.js` draw them (bar + inline SVG line; two cards in the right column above the scoring summary). Both are written from ESPN's usual summary layout and have not been checked against live data: a missing block just isn't drawn.
- Pickups tab (`pickups` in `NAV_ITEMS`, IPC `pickups`): `fetchTransactions` / `parseTransactions` in `engine.js` read `transactionsUrl` in `leagues.js` (`.../transactions?limit=100`, cached 10 min); `txKind` tags each row from its text (Trade, Signing, Waivers, Released, Roster move, Status, Draft). Leagues with `noTransactions` (NCAAF) are left out. `renderPickups` follows the Injuries conventions (league picker plus My teams / Whole league pills in the header, `visibleLeagues(..., true)`, `isShownFollowed`, `showAllHidden`). The feed's shape (`transactions[]` with `date`, `description`, `team`) is from memory and unverified.
- Leaders tab (named "Leaders" in the UI; the nav key stays `leaderboards` so saved sidebar orders keep working; IPC `leaders` with `{ key, category }`): `fetchLeaderboard` in `engine.js` reads ESPN's core API (`leadersUrl`, `seasonYear` in `leagues.js` names the season per sport, falls back one year) which lists leader categories per sport with `$ref` links; one request lists the categories (cached 15 min), then only the asked category's top `LEADER_ROWS` (10) athletes are resolved (`fetchAthlete`, cached 24 h, 6 at a time) and teams come from the league's team list (cached 24 h). Only `https://sports.core.api.espn.com` links are ever followed (`safeRef`). `renderLeaderboards` puts the category pills in the header (`state.lbCat` remembers one per league). Unverified against live data: if the tab is empty or errors, check `parseLeaders` and the URL first.
- Player panel: a player's name (Roster, Injuries, Leaders, box score) is a `playerName()` link with `data-player="league:id"`; one delegated click handler calls `openPlayer` in `renderer.js`, which opens a modal (`#pmodal`, Esc or a click outside closes it) from IPC `player` = `fetchPlayer` / `parsePlayer` in `engine.js` (cached 10 min, 60 entries). It reads ESPN's core API through `athleteUrl` / `athleteStatsUrl` in `leagues.js`: the athlete record for the bio and `seasons/<year>/types/2/athletes/<id>/statistics/0` for the stats (`splits.categories[].stats[]`, falling back one season when the current one is empty). The IPC handler only accepts a known league and a numeric id. The payload shapes are written from ESPN's usual layout and unverified against live data: if the panel shows a bio but no stats, check `parsePlayer` and the stats URL first.
- Seasonal themes: `seasonOf()` / `applySeason()` in `renderer.js` set `<html data-season="halloween|christmas">` for the week before and after Oct 31 (Oct 24 to Nov 7) and Dec 25 (Dec 18 to Jan 1), re-checked hourly; `styles.css` re-colours `--orange` / `--amber`, the background and the active tab under `:root[data-season=...]`. The `seasonalThemes` setting (default on, in `DEFAULT_ON` and both `main.js` defaults, "Appearance" group in Settings) turns it off. The mini scoreboard keeps its normal colours (its tokens must stay equal to `styles.css`).
- Schedules remembers its Day / Week / Month view in the `calView` setting (`rememberCalView` in `renderer.js`).
- Standings change alerts: the per-team `standings` alert type (in `DEFAULT_ALERTS` and `ALERT_TYPES`). `Engine.process` snapshots the league table (`standingsSnapshot`) the first time it sees a followed game live (`captureGameBase`, kept in `gameBase` by game id), and on the in-to-final transition `watchStandings` polls `fetchStandings` (90 s warm-up, then every 2 min, up to 45 tries) until the followed team's `recordSig` differs from the snapshot, meaning ESPN has counted the game. It then notifies once via `standingsChanges` (rank in its table, clinch marker), and only when something changed. Skipped in the postseason (`isPostseason`). Timers live in `standJobs` and are cleared by `Engine.stop`. The wording of clinch markers is in `CLINCH_TEXT`.
- Mini scoreboard overlay: a second frameless, opaque (`backgroundColor: OVERLAY_BG`, the app's `--bg` #1c1c1c), resizable, always-on-top `BrowserWindow` (`createOverlay` in `main.js`, page in `renderer/overlay.html` / `overlay.js` / `overlay.css`). It reuses `preload.js` and the same `games:get` / `games:update` feed as the main window (`onUpdate` in `main.js` sends to both) and shows only games with `state === 'in'`; with none it shows the next upcoming game. `updateOverlayVisibility()` is the single place that creates, shows (`showInactive`, so it never steals focus) or hides it, driven by `overlayEnabled` and `overlayAutoHide`; call it after changing either. **`overlayEnabled` and `overlayBounds` (`{ x, y, width }`) belong to the main process** (tray menu checkbox, dragging, resizing): the renderer toggles it through `api.setOverlay` (IPC `overlay:set`) and `'settings:save'` overwrites those two keys on the incoming object so a stale renderer copy can't undo them. **Do not make it transparent**: Electron 33 can't resize a transparent window on Windows (electron/electron#49173, only fixed in much newer versions). Only the width is user-resizable (`OVERLAY_MIN_W` 220 to `OVERLAY_MAX_W` 640, default `OVERLAY_W` 270, remembered via the debounced `rememberBounds` on `moved`/`resize`, which skips the disk write when nothing changed). The height always follows the content: the page reports its height through IPC `overlay:size` (it measures `#frame`, the card plus a 4px no-drag edge ring that keeps the drag area from covering the resize edges), and main unlocks the min/max size, applies the new content size at the user's current width, then locks min/max height to it, so only the width can be dragged. The page scales with the width: `applyScale` in `overlay.js` sets `--s` = window width / 270 (clamped 0.8 to 2.4) on `:root`, and `overlay.css` sizes everything in `rem` (`font-size: calc(16px * var(--s))`), so new layout sizes in that file must use `rem` too. Its color tokens (`--bg`, `--text`, `--muted`, `--line`, `--amber`, `--orange`, `--live`) are copies of the ones in `styles.css` and must stay equal to them; each game block is styled like an app game card and gets its teams' colors through `--a` / `--h`. Closing the main window for real (`keepInTray` off) also closes the overlay via `closeOverlay()`, otherwise its open window would keep the app alive. `closeOverlay()` removes the `closed` listener first so it isn't mistaken for the user turning it off. Position, resizing from the window edges, rounded corners and always-on-top behavior can only be verified on Windows.
- Season status: `isInSeason` in `engine.js` (IPC `seasons:status`) says a league is in season when it has games from 2 days ago to 10 days ahead (cached 3 h; on network errors it keeps the last answer or assumes in season). Two independent settings, **both default on**, decide which followed teams the renderer shows (see "Autohide settings" below for how they are stored): `hideOffSeason` ("Autohide out of season sports": the team's whole league is out of `state.activeLeagues`) and `hideEliminated` ("Autohide teams that are out": the team is in `state.outTeams`, filled from IPC `teams:out` = `fetchOutTeams` in `engine.js`). `hiddenReason(f)` in `renderer.js` is the one place that applies them; `shownFollows()`, `isShownFollowed()` and `gameShown()` build on it, and Scores, Recaps, Schedules, Standings (highlight and league picker) and Injuries (My teams and league picker) all use those. `visibleLeagues(extra, followedOnly)` with `followedOnly` true lists only leagues that still have a shown team, which is how a sport leaves when its season is over or every team in it is out. **Roster never uses any of this and the Select tab (nav key `teams`) lists every league and every followed team** (a hidden team could otherwise not be unfollowed). When every followed team is hidden, `showAllHidden()` shows a note with a Settings button. Nothing is hidden until the status is known (`state.activeLeagues` is null), and the engine and alerts are never affected. `fetchOutTeams` only says "out" on positive evidence: the team lost its newest playoff series (`playoffsOutcome`, which needs a clear winner), ESPN's standings mark it `e`, or (NHL/NBA only, because MLB/NFL/college have byes) the postseason has run `OUT_AFTER_DAYS` (3) and the team never appeared in it; any error means "alive". It looks back 75 days through `fetchPlayoffs(l, { back, keepDays })` (days older than 3 are cached for 6 h) and the renderer refreshes it every 30 min, when a team is followed, and when the switch is turned on (`refreshOutStatus`).
- UI conventions: every pill group lives in the header via `setActions(opts, current, onPick, picker)` in `renderer.js` (the `#hact` slot, cleared on each `render()`), on the same line as the title. Layout is pills on the left (league/team `picker` first, then a `|` divider, then the option pills), blue `.sub` text, a `|`, then the title on the right. Option pills: Scores/Recaps `By team`/`By status`, Injuries scope, Schedules Day/Week/Month. Pickers: league (Teams, Standings, Injuries) or team (Roster). Don't put pill rows inside `#view`. Recaps shows the last `RECAP_GAMES` (3) finals per followed team, searching back `RECAP_LOOKBACK_DAYS` (35). Scores and Recaps group by followed team by default (`groupBy` setting, defaults in two places in `main.js`).
- Versioning: `package.json` `version` is the app version (shown in Settings via IPC `app:version`). **Any feature added is a version change**: bump `version` in the same change that adds it (new feature = minor bump, e.g. 0.2.2 to 0.3.0; bug fix or tweak with no new feature = patch bump). Name the release zip `SportsChud-vX_Y_Z.zip` (e.g. `SportsChud-v0_3_0.zip`), and mention new features in `README.md`. `package-lock.json` is regenerated by `npm install`, not edited by hand.
- `updater.js`: update checker for the installed app. Reads `releases/latest` from the GitHub repo in its `REPO` constant (change it if the account or repo is renamed; `Install-SportsChud.ps1` has the same name), compares the tag with `app.getVersion()`, and on request downloads `SportsChud-Setup.exe`. The download goes to `SportsChud-Setup-<version>.exe.part` in the temp folder and is only renamed to `.exe` once the size matches, `looksLikeInstaller` passes ("MZ" header, over 1 MB) and, when the release asset carries a `digest` (`sha256:<hex>`), the SHA-256 matches; old installers in temp are cleaned first. Then `shell.openPath(dest)` opens the installer through Windows' normal launcher (so the UAC prompt can show); there is no helper script or child process, and SportsChud is NOT closed automatically. `state.installing` means the installer was opened (`installerPath` remembers it): `check()` becomes a no-op and a second `install()` just reopens the same file (UI: "Open installer again"), or reports it is gone. `onInstallerOpened` makes `main.js` set `updateReady`; from then on closing the window, tray Quit and `before-quit` all go through `shutdownAll()` (engine, updater, overlay, tray, window, `app.quit()`, `app.exit(0)` backstop after 4 s) instead of hiding to the tray, so no SportsChud process is left for the NSIS installer's own "is the app running?" check (which can also close the app itself). Before an installer is opened, `keepInTray` behaves as usual. `second-instance` is ignored while quitting. After a successful open the installer file is never deleted by the app. Earlier versions (0.10.1 and before) used a detached PowerShell/cmd helper that waited for exit; it was removed on purpose, don't bring it back. A bad download or an installer that can't start leaves the app running with `state.error`. Only active when `app.isPackaged` on Windows. The `checkForUpdates` setting (default on, in `DEFAULT_ON`) only controls the automatic check. IPC: `update:state`, `update:check`, `update:install`, event `update:state`. The release tag must equal `package.json` `version`; CI enforces it. The update flow can only be verified on Windows with a real release.
- Sidebar: `NAV_GROUPS` in `renderer.js` fixes the groups and default order (Games / Stats / Teams, drawn as yellow `.navgroup` dividers); `NAV_ITEMS` holds icon and label (the `teams` tab is labelled "Select"). The ▲/▼ reorder only moves an item inside its group; the saved order is the `navOrder2` setting (the older flat `navOrder` is ignored). Playoffs and Activity only show when `navVisible`, and a group with nothing visible draws no divider.
- `preload.js`: `contextBridge` API exposed as `window.api`. Every IPC channel used by the renderer must be listed here.
- The Activity tab is hidden from the sidebar until the first alert of the session (`navVisible` / `activityVisible` in `renderer.js`); it appears when the first `activity` event arrives. The `activityAutoHide` setting (default on) controls this: when off, the tab is always shown.
- Autohide settings: Settings (`renderSettings` in `renderer.js`) is split into yellow-headed groups: Updates, Startup and tray, Mini scoreboard, Autohide, Troubleshooting, Reset. The autohide switches `playoffsAutoHide` (default on), `activityAutoHide` (default on), `hideOffSeason` (default on) and `hideEliminated` (default on) sit under "Autohide"; `overlayAutoHide` (default off) sits with the other Mini scoreboard switch. `hideOffSeason` was off before 0.8.0, so `loadSettings` in `main.js` switches it on once for settings saved earlier (flag `offSeasonDefaultApplied`) and respects the saved choice after that. `showTestAlert` (default off, in the general list, not under Autohide) controls whether the sidebar's Send test alert button is shown (`applyTestButton`). When you add a new autohide behavior, add its switch to the matching group list there (`autohide`, or the group of the feature it hides). Settings that default to on are listed in `DEFAULT_ON` in `renderer.js` (a missing key counts as on) and must also be set in both default places in `main.js`.
- `renderer/`: `index.html`, `renderer.js` (all main-window views), `styles.css`, `icon.png` (sidebar logo), and the mini scoreboard page (`overlay.html` / `overlay.js` / `overlay.css`).
- `assets/`: `icon.png` (source) and `icon.ico` (rendered from it, used for the exe/taskbar/shortcut).
- Icon rendering tools (`*.whl` wheels) are git-ignored and not part of the app.

## Settings and storage
- Settings live in `settings.json` in Electron's `userData` folder (`%APPDATA%\SportsChud`). Defaults are defined in `main.js` in two places (the `settings` initializer and the `app:reset` handler). Keep them in sync when adding a setting. New per-team alert types go in `DEFAULT_ALERTS` (`main.js`) and `ALERT_TYPES` (`renderer.js`); `loadSettings` backfills them onto already-saved teams.
- `loadSettings` also reads the legacy `%APPDATA%\Gametime\settings.json` from before the rename.
- `SportsChud.log` in the same folder is a small diagnostic log (single-instance and second-launch events).

## Window, tray and taskbar behavior (the fiddly part)
- `keepInTray` (default true): closing the window calls `win.hide()` instead of quitting. The app keeps running and polling from the tray icon. Quit via the tray menu. When `keepInTray` is false, closing quits.
- A hidden window has no taskbar button on Windows. The only ways back are the tray icon, a notification click, or launching the app again.
- Launching again is caught by `requestSingleInstanceLock` + the `second-instance` event, which calls `showWindow()`. This is how the pinned taskbar icon and the desktop shortcut reveal a hidden window. The second process just quits.
- Always bring the window back with `showWindow()`, never ad hoc `win.show()`. It restores, shows, and force-focuses (Windows may otherwise leave a background window unfocused).
- Taskbar identity: AppUserModelID is `com.sportschud.app` (`APP_ID`). It is set on the process, the window (`setAppDetails`, with `relaunchCommand`) and the desktop shortcut so pinning shows the SportsChud icon and relaunches the right thing. Explorer can't read icons from inside `app.asar`, so `stableIcon()` copies `icon.ico` into `userData` and points at that. `appIcon()` returns that on-disk copy and is what every `BrowserWindow` (main and overlay) and `Notification` uses, never the path inside the asar. The installed exe's own icon comes from electron-builder: `win.signAndEditExecutable` must NOT be set to `false` in `package.json` (that flag skips embedding `assets/icon.ico` in `SportsChud.exe`, which is what makes Windows show Electron's logo in the taskbar and shortcuts). If a build ever fails fetching winCodeSign, fix that on the build machine rather than turning the flag back off.
- The desktop shortcut is created once (flag file `.desktop-shortcut`), refreshed on every start if it exists, and never recreated if the user deleted it.
- `--hidden` + `startSilently` starts with the window hidden (login item). `createWindow(true)` overrides that when something explicitly asks for the window.

## Conventions
- Keep ESPN access inside `leagues.js` and `engine.js`. The feed is undocumented and may change.
- Renderer has no Node access: `contextIsolation` is on and the CSP in `index.html` only allows `self` scripts. New main-process features go through `preload.js` + `ipcMain.handle`.
- Keep dependencies minimal. The app uses no runtime npm packages, only Electron and electron-builder as dev dependencies.
- Don't edit `package-lock.json` by hand.
